# 安全维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 可利用注入(SQL/命令/XSS/模板/反序列化);`${}` 拼接用户输入进 SQL、LIKE 拼接;eval()/Function()/字符串形式 setTimeout/setInterval;innerHTML 插入用户输入;硬编码密钥/凭证/token;密码/密钥/连接串明文存储;认证绕过或敏感操作缺授权;缓冲区溢出(strcpy/sprintf/无边界检查)。
- **65–84:** 弱加密或自实现加密;敏感数据(PII/密码/token)被日志或响应泄露;信任边界缺输入校验;SSRF / 路径穿越 / IDOR（可直接导致 RCE 或 secret 泄露时升至 85-100）;整数溢出/截断/UTF-8 边界错误;非 HTTPS 或不校验证书;修改原生对象原型(原型链污染)。
- **40–64:** 关键接口缺限流防爆破;错误信息泄露内部细节(堆栈/路径/SQL);不安全默认配置;权限范围过宽;document.write 注入风险（若直接注入用户输入则升至 85-100）。
- **20–39:** 缺安全响应头;尚不可利用的不规范权限设置。
- **1–19:** 纵深防御层面的可选加固缺失。
- **0:** 未发现安全问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 可形成可利用攻击路径（注入、越权、敏感数据泄露、命令执行）
  - 影响认证、授权、数据边界或核心资产
  - 攻击门槛低（无需高权限、可远程、可批量）
  - 利用步骤清晰且可复现
  - 把「操作成功」直接映射为门禁放行、或解锁/bypass 调用绕过未完成的前置校验、扩大作用域，破坏授权边界
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅理论风险，无法从变更证明可触发
  - 依赖外部假设过多
  - 影响面描述模糊
