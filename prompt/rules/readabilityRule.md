# 可读性维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 代码晦涩导致审查者无法准确判断其行为，或审查代价远超常规。
- **65–84:** 逻辑极度令人困惑;命名严重误导(名实不符);毫无结构导致无法判断行为。（此档严重问题经加分应达到 80 分以上）
- **40–64:** 命名差(单字母/无意义缩写);密集且无解释的复杂逻辑;深层嵌套严重伤害理解;嵌套三元表达式。
- **20–39:** 偶尔的不清晰命名;为表意可拆分的略长函数/长行;复杂业务逻辑缺注释。
- **1–19:** 声明处拼写错误;log/异常消息拼写错误;空白、格式、命名小润色。
- **0:** 清晰易读,未发现问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 命名或结构明显阻碍理解，影响维护效率
  - 复杂度过高（深层嵌套、逻辑跳转混乱）且影响正确理解
  - 抽象层级混杂，阅读路径不连贯
  - 问题可通过具体片段稳定定位
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅主观可读性偏好
  - 无明确阅读障碍证据
  - 影响范围描述不完整
