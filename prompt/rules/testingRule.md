# 测试维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 新增的关键逻辑完全没有测试;假测试(永远通过/无有效断言/被注释禁用)。
- **65–84:** 核心路径缺测试;修 bug 却没有回归测试;引入了 flaky 测试（影响关键 CI 通道的 flaky 测试升至 85-100）。
- **40–64:** 缺少错误/负向用例;重要分支覆盖不足;测试与实现细节强耦合(脆弱)。
- **20–39:** 次要边界缺测试;断言过弱(只断言"不抛异常")。
- **1–19:** 测试命名、组织结构的小问题。
- **0:** 测试充分,未发现问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 关键逻辑缺少必要测试，导致正确性无法验证
  - 边界/异常路径未覆盖，缺陷逃逸风险高
  - 断言无效或脆弱，无法拦截回归
  - 可明确给出缺失场景与预期结果
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅测试写法偏好，不影响验证有效性
  - 变更过小且无需额外测试即可验证
  - 场景描述不完整
