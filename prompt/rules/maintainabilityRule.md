# 可维护性维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 任何局部修改都会扩散至多处、无法安全进行;承担过多职责的上帝函数/类处于关键路径且耦合到无法分解。
- **65–84:** 严重高耦合或大段重复贯穿核心逻辑;完全缺乏关注点分离;大量魔法数字散布业务逻辑;业务相关硬编码(URL 路径、业务编号);死代码(永不可达分支、声明未引用的变量、无保留意图的大段注释代码)。
- **40–64:** 过长函数/过深嵌套;模块边界不清;明显违反单一职责;可提取的重复逻辑。
- **20–39:** 中等程度重复;少量魔法值;轻微抽象层级混乱;未用语言惯用法简化(Kotlin `when`/`data class`/单表达式函数;C++ 该用 RAII/智能指针/STL 却手动管理)。
- **1–19:** 可有可无的小结构问题;`auto` 滥用;命名风格小问题。
- **0:** 未发现可维护性问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 结构性缺陷明显（重复逻辑、耦合失控、职责混乱）
  - 显著增加后续修改成本或引发高回归风险
  - 扩展点被硬编码封死，演进困难
  - 问题定位和复现边界清楚
  - 可变/链式查询构造对象在多次查询间共享，链式状态相互污染，导致结果错误或回归风险
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅编码风格偏好，不影响可维护性
  - 证据不足，无法在 diff 中确认
  - 成本评估不明确
