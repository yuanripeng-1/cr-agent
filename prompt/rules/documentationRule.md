# 文档维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:**对外公共 API 契约非显而易见却完全无文档,几乎必然被误用。
- **65–84:** 复杂/对外接口缺文档;文档误导或已过时(与实现不符)（若误导直接影响安全或业务决策则升至 85-100）;`unsafe` 块/`unsafe impl Send|Sync` 缺安全理由(Rust);非显而易见的关键决策缺"为什么"。
- **40–64:** 公共函数缺 docstring;复杂算法无解释;存在与代码不一致的陈旧注释;`any` 类型无解释注释;intentional fall-through 缺注释。
- **20–39:** 内部辅助函数文档稀疏;少量文档缺口。
- **1–19:** 文档中的拼写、格式问题。
- **0:** 文档完整,未发现问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 公共接口或关键配置缺少必要文档说明
  - 文档与实现不一致，可能误导使用者
  - 复杂逻辑缺少关键解释，维护风险上升
  - 问题影响范围和误用后果清晰
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅文案风格偏好，不影响正确理解
  - 缺少可验证证据
  - 影响描述不完整
