# 性能维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 热点路径 O(n²)+ 且 n 可能很大;无界内存增长;关键路径 N+1 查询;循环内执行 DB 查询;async 中阻塞 I/O 或锁内阻塞;ArkUI `build` 方法内创建对象/闭包/返回样式的函数（ArkUI 平台专属；非 ArkUI 项目忽略）。
- **65–84:** 循环内重复执行昂贵计算/查询;缺索引导致全表扫描（高数据量场景下可升至 85-100）;一次性加载超大数据集无分页;>20 项大列表用 `ForEach` 而非 `LazyForEach`（ArkUI 平台专属）;循环内创建 `Regex` 等重对象。
- **40–64:** 不必要的拷贝/序列化/中间集合(可用 Sequence/迭代器);缺分页或批处理;数据结构选型不当(list 频繁查找应用 HashMap/HashSet);重复子查询;已知容量却未预分配。
- **20–39:** 可消除的微小低效;过早小分配;手写循环可用 STL 算法替代。
- **1–19:** 收益可忽略的低效。
- **0:** 未发现性能问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 确定会导致明显性能退化（复杂度恶化、热点路径阻塞、资源泄漏）
  - 会在中高并发下放大（队列堆积、吞吐下降、尾延迟抖动）
  - 直接影响核心链路 SLA
  - 可通过压测/推导稳定复现
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅微优化建议，无明确收益
  - 缺少关键上下文，无法证明影响
  - 影响范围或触发条件不清晰
