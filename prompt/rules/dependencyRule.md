# 依赖维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 引入带已知 critical/high CVE 的依赖;许可证与项目不兼容;关键路径依赖已废弃/无人维护;打包进了密钥/凭证/含密测试夹具（若已在 security 维度报告，本维度可不重复上报）。
- **65–84:** snapshot 版本进生产(gradle/pom);`latest`/`*`/通配版本(npm/cargo);未固定的 `git` 依赖(无 `rev`/`tag`/可复现策略);依赖冲突(同一依赖同时在 `dependencies` 与 `devDependencies`)。
- **40–64:** 依赖严重过时(落后多个主版本);引入大量传递依赖造成膨胀;功能重复的依赖;依赖放错 section(应在 dev/build/target-specific);`scripts` 用到的工具(eslint/jest/prettier)未声明在 `devDependencies`。
- **20–39:** 标准库即可满足却引入外部依赖;小版本漂移;新包未声明 `edition`;库未声明 `rust-version`(有 MSRV 政策时);默认 feature 过重。
- **1–19:** 依赖声明排序/分组/元数据(license/repository/description)缺失。
- **0:** 未发现依赖问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 引入高危漏洞依赖或严重供应链风险
  - 版本策略不安全（未锁定、范围过宽、不可复现）
  - 许可证风险或与项目策略冲突
  - 存在可替代且更安全/更轻量方案
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅主观库偏好，不构成真实风险
  - 缺少证据（CVE/版本策略/许可条款）
  - 影响描述不完整
