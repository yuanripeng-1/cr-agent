# 业务维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 核心逻辑产出错误结果;违反明确业务规则;业务数据被错误写入/损坏;关键状态机进入非法状态;生产代码关键路径中几乎必然触发的 NPE 或无终止条件的死循环/递归。
- **65–84:** 关键边界处理错误(0/负/空集合/越界/并发);check-then-act 竞态、非原子复合操作、非线程安全集合的并发写（金融/支付/库存场景升至 85-100）;缺失影响业务结果的必要校验;要求幂等却不幂等且有副作用;SQL 条件逻辑错误(WHERE 的 AND/OR 混用、JOIN 条件缺失或字段错误)。
- **40–64:** 需求覆盖不完整;业务规则仅部分实现;非核心路径边界遗漏;switch 漏 break 导致意外穿透;逻辑表达式缺括号致优先级偏离意图。
- **20–39:** 低影响边界未处理;行为有歧义但影响小。
- **1–19:** 面向业务的措辞/展示小不一致。
- **0:** 未发现业务逻辑问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 明确违反 MR/PRD 的核心业务目标，且会导致结果错误
  - 关键业务分支缺失（边界值、状态流转、额度/条件校验）
  - 会造成真实业务损失（计费、结算、权益、订单、审批结果错误）
  - 问题可稳定复现，触发条件清晰
  - 聚合状态字段漏算应参与判定的子状态、跨接口同名字段口径不一致、或把「操作成功」直接当作授权放行
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅为实现偏好差异，不影响业务正确性
  - 证据不足，无法从 diff 直接证明
  - 影响范围不明确或复现路径不完整
