# 错误处理维度评分规则

## 单条问题评分（score: 0-100）


**初次判定危险严重度分档（单条问题同时符合多个档位时，取最高档为基准分）**
- **85–100:** 关键错误被静默吞掉致数据丢失/损坏;裸 catch 在关键路径隐藏失败;错误路径资源泄漏(malloc 未 free、文件/连接未 close、锁未释放);double-free / use-after-free。
- **65–84:** I/O / 网络 / DB 调用完全无错误处理;异常未正确传播;部分失败后无回滚致状态不一致;（Rust）可恢复路径用 `unwrap`/`expect`/`panic!`;`Result`/`Option` 被忽略或映射为误导性默认值;（Rust）`async` 任务 `JoinHandle` 被丢弃而失败仍需观测;（Kotlin）`GlobalScope` 协程泄漏。
- **40–64:** 笼统 catch-all / `catch(...)` 掩盖不同错误;缺清理逻辑(未用 RAII/`use`/`finally`/`defer`);错误模型不一致;外部调用无超时/重试/退避;错误过早转字符串丢失上下文。
- **20–39:** 低风险路径少量遗漏处理;async 缺 try-catch 但影响小。
- **1–19:** 错误信息措辞、日志级别的小问题。
- **0:** 未发现错误处理问题。


**加减分策略**
先基于"**初次判定危险严重度分档**"确定档位，取该档位中间值作为基准分，然后再按下列因素调整:单因素 ±5~15,同向可累积,但单次调整最多 ±20（含跨档）；调整后 clamp 到 `[0,100]` 并记录命中因素。
- 加分项（每项 +5~+15，影响越直接越高）：
  - 存在静默失败、异常吞噬、错误状态未暴露
  - 缺少关键恢复/回滚/超时机制，导致状态不一致
  - 错误信息不可操作，排障成本高
  - 故障触发条件清晰且可复现
  - 新增 handler 首次使用注入依赖前缺少空值/可用性防护（可致崩溃）、或把正常「未命中/NotFound」误判为系统错误返回
- 减分项（每项 -5~-15，影响越不确定越低）：
  - 仅日志格式或文案偏好差异
  - 缺少证据，无法确认会造成失败或恢复失效
  - 影响范围不明
